# Модель и усилие

Тяжёлая модель нужна там, где ошибка дорогая или незаметная; дешёвая — там, где задача расписана и проверяется командой. Названия моделей меняются: перед планом сверься со списком моделей, доступных в агенте, и обнови таблицу этого файла, если она устарела.

## Выбор по работе

| Работа | Модель | Усилие | Почему |
|--------|--------|--------|--------|
| Аудит, код-ревью, поиск причин | тяжёлая | high | пропущенная находка дороже всей сессии |
| План для дешёвых исполнителей | тяжёлая | high | ошибка плана размножается во всех шагах |
| Директор: ведение плана, проверка чекпоинтов | тяжёлая | high | решает, что принято; проверяет чужую работу |
| Перенос или реструктуризация без потерь, оценщики, тестовые стенды | тяжёлая | high | ошибка обесценит всё последующее |
| Расписанная правка с командой проверки | средняя | medium | думать не о чем, нужна аккуратность |
| Оркестрация прогонов по готовому протоколу | средняя | medium | механика, но с ручной оценкой |
| Массовые однотипные прогоны, испытуемый на стенде | дешёвая | — | дёшево; на слабой модели виден эффект правил |

**xhigh / max** — только для задачи, где high уже не справился. Без цикла «прогнал → исправил» лишнее усилие уходит на рассуждения.

## Claude

| Класс | Модель |
|-------|--------|
| тяжёлая | Opus (сейчас Opus 5.5) |
| средняя | Sonnet (сейчас Sonnet 5.5) |
| дешёвая | Haiku (сейчас Haiku 5.5) |

Ориентиры стоимости из реальной работы (облачные сессии Claude Code, 2026-10). Директор дополняет таблицу фактическими ценами из журналов планов:

| Сессия | Модель | Цена |
|--------|--------|------|
| Разбить скилл на ядро и справочники без потерь | Opus, high | ~$2 |
| Мелкая расписанная правка с PR | Sonnet | <$1 |
| Тестовый стенд: 5 кейсов, оценщики, эталоны | Opus, high | ~$6 |
| 30 прогонов Haiku через субагентов + ручная оценка | Sonnet-оркестратор | ~$11 |
| 4 правки + 9 прогонов | Sonnet-оркестратор | ~$3,6 |

Оркестратор на средней модели может стоить больше прогонов, которые он запускает: каждое чтение diff и отчёта идёт через его контекст. Чтобы экономить, не читай трассы исполнителей целиком и проси одну строку оценки на прогон.

## Codex

Тот же принцип: тяжёлые роли (аудитор, планировщик, проверяющий) — самая сильная доступная модель Codex с высоким уровнем рассуждения; исполнитель — быстрая и дешёвая модель. Конкретные названия и уровни смотри в списке моделей Codex на момент работы и впиши их в шаги плана.

Смешанная схема — исполнитель Codex, проверяющий Claude — экономит лимит Claude: дорогая модель тратит токены только на чекпоинты ([codex.md](codex.md)).

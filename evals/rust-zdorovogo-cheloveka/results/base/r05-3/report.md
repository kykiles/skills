Оптимизирована памяти и производительность крейта logtop. 

**Ключевые изменения:**
- Удалена функция `requests()` которая создавала Vec<String> для каждой строки лога (главная причина избыточного использования памяти)
- Переработана `parse_line()` чтобы работала со `&str` и использовала итератор вместо Vec
- `top_paths()` и `bytes_by_status()` теперь обрабатывают лог напрямую через `log.lines()` без промежуточного вектора, используя HashMap<&str> вместо HashMap<String> при обработке

**Результат:** Память теперь зависит только от количества уникальных путей и кодов ответа, а не от размера лога. Выделения памяти уменьшены с нескольких на каждую строку до выделений только для HashMap и конечного результата.

**Проверки:** ✓ Все тесты (2), ✓ Clippy (0 warnings), ✓ Форматирование, ✓ Публичный API не изменился

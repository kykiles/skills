## Оптимизация logtop: устранение избыточных выделений памяти

### Изменения

**Файл: /tmp/ws/base/r05-1/src/lib.rs**

1. **Структура Request**: изменена с `path: String` на `path: &'a str` - теперь хранит ссылку на подстроку исходного лога вместо копии

2. **Функция parse_line**: 
   - Принимает `&str` вместо `String`
   - Парсит поля построчно через `split_whitespace().next()` вместо создания промежуточного вектора
   - Возвращает `Request<'_>` с lifetime для безопасности

3. **Удалена функция requests**: создавала промежуточный вектор со всеми строками лога - это был источник лишних выделений

4. **Функция top_paths**:
   - Используется `HashMap<&str, usize>` вместо `HashMap<String, usize>`
   - Итерирует по `log.lines()` напрямую, минуя промежуточный вектор
   - Memory allocation только для уникальных путей, а не для каждой строки логa

5. **Функция bytes_by_status**: аналогичная оптимизация - сразу итерирует по `log.lines()`

### Результаты оптимизации

- **Использование памяти**: зависит только от числа уникальных путей и кодов ответа (O(n_unique)), а не от размера лога (O(n_total))
- **Выделения памяти**: исключены множественные malloc/free на каждую строку логa
- **Публичный API**: сигнатуры функций `top_paths` и `bytes_by_status` остались без изменений

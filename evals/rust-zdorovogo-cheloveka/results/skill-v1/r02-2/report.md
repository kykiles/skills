## Исправлены все проблемы безопасности в библиотеке `pak`

**Файл:** `/tmp/ws/skill-v1/r02-2/src/lib.rs` (+74 строк)

### Что изменено:

1. **Добавлен лимит на количество записей**: Константа `MAX_RECORDS = 65536` препятствует выделению гигабайтов памяти на основе недоверенного заголовка. Проверка вставлена в `parse()` перед `Vec::with_capacity(count)`.

2. **Исправлено переполнение при сложении**: Строка 83 раньше паниковала с `attempt to add with overflow` при `offset + len`. Теперь используется `checked_add()` с преобразованием в `usize` и возвращением ошибки `OutOfBounds` вместо паники.

3. **Исправлена потеря данных при приведении**: Раньше `u64::from_le_bytes() as u32` молчаливо обрезал значения > u32::MAX. Теперь используется `u32::try_from(offset)` с проверкой ошибки.

4. **Защищен метод `get()`**: Заменена опасная индексация `&self.data[start..start + len]` на `self.data.get(start..end)` с безопасной проверкой границ через `checked_add()`.

5. **Добавлена новая ошибка**: Вариант `Error::TooManyRecords` для случаев когда архив заявляет > 65536 записей.

### Новые тесты:

- `rejects_too_many_records`: Проверяет лимит на 65536 записей
- `rejects_offset_overflow`: Воспроизводит первый инцидент (panic при overflow)
- `rejects_offset_too_large`: Проверяет что offset > u32::MAX отклоняется
- `rejects_huge_memory_request`: Проверяет что 12-байтный файл с 100000 записей не вызывает OOM (просто проверяет лимит на 65536)

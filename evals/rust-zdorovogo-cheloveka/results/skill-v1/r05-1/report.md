## Оптимизация logtop - память теперь зависит от кол-ва уникальных путей/кодов, не от размера лога

### Что изменено
Реактивирована структура обработки логов в `/tmp/ws/skill-v1/r05-1/src/lib.rs`:

**Ключевые оптимизации:**
1. **parse_line**: теперь принимает `&str` вместо `String` → нет выделения памяти для каждой строки
2. **Request**: хранит `&'a str` для пути вместо `String` → zero-copy подход
3. **Удалена функция requests()**: была непроизводительным посредником, выделявшим Vec для всех строк лога
4. **top_paths** и **bytes_by_status**: обрабатывают строки ленивым итератором через `log.lines()` вместо создания промежуточных Vec'ов
5. **HashMap<&str, usize>**: вместо HashMap<String, usize> → нет clone'ов при вставке
6. **Отсутствуют множественные clone()**: путь копируется в String только в конце, в результате функции

**Результат:** 
- Память зависит только от кол-ва разных путей и кодов ответа, а не от размера лога
- Множество malloc/free вызовов устранены - обработка строк идёт прямо из исходного буфера
- Очищено 6 строк кода (50→44 строк), код стал проще и быстрее

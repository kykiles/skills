# Испытание срабатывания `direktor`

Проверяет, загружает ли Claude Code скилл по запросу пользователя: 8 запросов, где скилл нужен, и 8, где не нужен (включая похожие: «аудит сервера», «код-ревью», «план поездки»). Запросы — [queries.tsv](queries.tsv).

## Как устроено

- Каждый прогон — новый `claude -p` в свежей копии [fixture/](fixture/) (два плана по формату скилла и аудит), в `.claude/skills/` — только испытуемый `direktor`.
- Сработал — значит, за первые 3 хода был вызов `Skill` с `direktor` ([parse.py](parse.py)).
- Запуск: `./run.sh <каталог скилла> <метка> [прогонов=1] [модель=sonnet]` → `results/<метка>.tsv` и сводка. Цель по гайду Anthropic — не меньше 90% верных.

## Итоги (2026-10-08, Sonnet, по 2 прогона на запрос)

| Версия | Верно | Цена | Промахи |
|--------|-------|------|---------|
| `old` — описание из `main` | 29/32 | $1,95 | «Выполни шаги 2–3 из PLAN.md» ×2, «Продолжи PLAN.md» ×1 |
| новое описание | 30/32 | $2,01 | «Выполни шаги 2–3 из PLAN.md» ×2 |
| `new` — новое описание + строка о скилле в шапке `PLAN.md` | 32/32 | $2,16 | — |

Лишних срабатываний не было ни разу. Запрос исполнителя «выполни шаги из PLAN.md» модель решала сама: читала план и бралась за шаги, не загружая скилл. Помогла не правка описания, а строка в шаблоне плана ([plan-format.md](../../direktor/references/plan-format.md)): план — точка передачи работы, поэтому указание на скилл должно быть в нём. Результат строки «новое описание» перезаписан последующим прогоном, файла нет.

## Ограничения

- Одна модель (Sonnet), 2 прогона — ориентир, а не статистика.
- Установлен только `direktor`: конкуренция с похожими скиллами (например, аудит сервера) не проверялась.
- Только Claude Code; Codex и claude.ai не проверялись.

## Исправления в пакете batch

### Проблемы, которые были исправлены:

1. **Растущее число горутин при ошибках в fn**: При ошибке функция возвращала управление, но worker горутины оставались в `for j := range jobs`, ожидая новые задания. Они не получали сигнала о завершении, что приводило к утечкам.

2. **Вызовы fn в закрытое соединение после отмены ctx**: Когда ctx отменялась, главная функция возвращала управление, но worker горутины продолжали выполняться. Они пытались отправить результаты в канал `outcomes`, который никто не читал, вызывая блокировку.

### Что изменено:

**Файл: `/tmp/claude-0/-home-user-skills/8db0c349-fe6f-5994-8f93-8a7d3bda3742/scratchpad/ws/skill-v3-1/batch/batch.go`**

- Добавлена `sync.WaitGroup` для отслеживания всех горутин (workers + sender)
- Создан собственный контекст с `context.WithCancel` и отменой при первой ошибке
- Канал `outcomes` буферизирован на `workers` элементов, чтобы горутины могли отправить результаты
- Горутина-отправитель jobs добавлена в WaitGroup и может быть остановлена через context
- Добавлен `wg.Wait()` перед возвращением для гарантии завершения всех горутин
- Возвращение `nil` при ошибке (соответствие контракту)

**Файл: `/tmp/claude-0/-home-user-skills/8db0c349-fe6f-5994-8f93-8a7d3bda3742/scratchpad/ws/skill-v3-1/batch/batch_test.go`**

## Исправления в пакете batch

### Проблемы (решены)

1. **Утечка горутин после ошибок**: ProcessAll возвращала управление без ожидания завершения горутин-обработчиков, нарушая контракт из doc-комментария.

2. **Вызовы fn после отмены**: При отмене контекста или ошибке горутины продолжали обрабатывать элементы и вызывать fn с закрытым соединением (например, с БД).

### Изменённые файлы

**`/tmp/claude-0/-home-user-skills/8db0c349-fe6f-5994-8f93-8a7d3bda3742/scratchpad/ws/skill-v3-2/batch/batch.go`**
- Добавлен импорт `"sync"`
- Добавлен внутренний контекст `context.WithCancel(ctx)` для управления отменой горутин
- Добавлена `sync.WaitGroup` для отслеживания всех горутин-обработчиков
- Изменён буфер канала `outcomes` с 0 на `workers`, чтобы горутины не блокировались при отправке результатов
- Каждая горутина-обработчик теперь:
  - Добавляется в `WaitGroup` перед запуском (`wg.Add(1)`)
  - Вызывает `defer wg.Done()` для сигнализирования о завершении
  - Проверяет отмену контекста перед отправкой результата
- При ошибке вызывается `cancel()` для остановки остальных горутин
- Главный цикл дождаётся `wg.Wait()` перед возвратом результатов
- Обработка ошибок защищена мьютексом для отслеживания первой ошибки

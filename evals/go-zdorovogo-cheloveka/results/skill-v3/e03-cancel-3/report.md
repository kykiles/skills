## Исправление ProcessAll в пакете batch

### Проблемы, которые были исправлены:

1. **После ошибок в fn растёт число горутин** - worker-горутины продолжали работать и выполнять fn() даже после ошибки, потому что не было механизма их остановки.

2. **После ProcessAll вернула ошибку, иногда ещё выполняются вызовы fn** - горутины продолжали работать и писать в базу после того, как соединение уже закрывалось, потому что контекст не отменялся.

### Внесённые изменения в `/tmp/claude-0/-home-user-skills/8db0c349-fe6f-5994-8f93-8a7d3bda3742/scratchpad/ws/skill-v3-3/batch/batch.go`:

1. **Добавлен внутренний контекст с отменой** - `ctx, cancel := context.WithCancel(ctx)` с `defer cancel()` гарантирует контролируемую отмену при ошибке.

2. **Добавлен WaitGroup** для отслеживания всех горутин (worker-горутины, горутина sendJob).

3. **Добавлен буфер для канала outcomes** размером `workers` для предотвращения блокировки.

4. **Горутина sendJob теперь**:
   - Добавляется в WaitGroup
   - Проверяет контекст перед отправкой элементов (выходит при ctx.Done())
   - Закрывает канал jobs через defer

5. **Worker-горутины теперь**:
   - Добавляются в WaitGroup
   - Завершаются через defer wg.Done()

6. **Добавлена горутина-closer**, которая закрывает outcomes после завершения всех workers через wg.Wait().

7. **Главный цикл изменён**:
   - Использует `for o := range outcomes` для чтения всех результатов
   - Отменяет контекст при первой ошибке: `cancel()`
   - Обязательно читает все результаты перед выходом
   - Проверяет ошибку контекста в конце функции

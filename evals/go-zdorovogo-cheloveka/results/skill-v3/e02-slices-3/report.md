## Исправлена проблема в пакете cmdargs

**Проблема:** При запуске нескольких команд с общим профилем аргументов первой команде оказывались аргументы второй. Причина была в функциях `Build` и `WithoutEmpty`, которые нарушали контракт о неизменяемости входных данных.

**Корневая причина:** Обе функции работали со срезами, указывающими на тот же базовый массив. Когда `Build` использовал `append(base, extra...)`, она добавляла данные в тот же буфер, перезаписывая предыдущие результаты. Функция `WithoutEmpty` тоже использовала `args[:0]`, создавая срез того же буфера.

**Изменения:**

1. **cmdargs.go** (6 строк измено, 2 удалено):
   - `Build`: Теперь копирует `base` в новый срез перед добавлением `extra`, соблюдая контракт о неизменяемости входных данных.
   - `WithoutEmpty`: Теперь использует `make([]string, 0, len(args))` вместо `args[:0]`, чтобы не модифицировать буфер входных данных.

2. **cmdargs_test.go** (добавлено 18 строк):
   - Добавлен новый тест `TestCommandMultiple`, который воспроизводит исходную проблему и проверяет корректность работы при нескольких вызовах `Command` с разными аргументами.

**Проверки запущены и пройдены:**
- `go test -v`: ✓ 3/3 тестов пройдено (включая новый TestCommandMultiple)
- `go test -race`: ✓ все тесты пройдены с детектором гонок
- `go vet`: ✓ ошибок не найдено
- `gofmt -l`: ✓ форматирование правильное

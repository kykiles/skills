Исправлены две критические проблемы в функции `ProcessAll`:

#### 1. Утечка горутин после ошибок
**Проблема**: При возвращении ошибки из fn, функция возвращала управление сразу, оставляя горутины-воркеры заблокированными на попытке отправить результаты в channel outcomes, который никто не читал.

**Решение**:
- Добавлен `sync.WaitGroup` для отслеживания всех воркеров
- Реализовано асинхронное ожидание завершения воркеров в отдельной горутине (строки 126-130)
- После закрытия канала jobs воркеры выходят из цикла и завершают работу

#### 2. Вызовы fn после завершения ProcessAll
**Проблема**: После возврата ошибки или отмены контекста, отправляющая горутина продолжала отправлять новые элементы в channel jobs, заставляя воркеры вызывать fn на элементах, даже после того как ProcessAll вернул управление.

**Решение**:
- Буферизация канала outcomes: увеличено с `len(workers)` до `len(items)` (строка 33)
- Пересоединение логики отправки и чтения: теперь функция проверяет доступные результаты перед попыткой отправить новый элемент (строки 60-82)
- При возникновении ошибки, сразу устанавливается флаг и выход из цикла отправки (строка 76)
- После закрытия jobs функция дожидается получения результатов только от уже запущенных воркеров (строка 133: `receivedCount < sentCount`)

### Ключевые изменения кода

1. Добавлен импорт `sync` (строка 6)
2. Буферизованный channel outcomes: `make(chan outcome, len(items))` (строка 33)
3. Переработана логика цикла отправки/чтения (строки 59-119):
   - Проверка результатов перед отправкой нового элемента
   - Выход при первой ошибке или отмене контекста
4. Добавлен обработчик завершения воркеров через отдельную горутину (строки 126-130)
5. Изменена логика чтения оставшихся результатов (строки 133-148):
   - Чтение только результатов от отправленных элементов
   - Завершение при завершении всех воркеров

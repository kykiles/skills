## Исправления в пакете batch

### Проблемы
1. **Утечка горутин после ошибок в fn** - после ошибки в функции-обработчике число горутин продолжает расти
2. **Выполнение fn после возврата ProcessAll** - после того как ProcessAll вернула ошибку или отмену, иногда ещё выполняются вызовы fn и пишут в закрытое соединение

### Решение
Внесены следующие изменения в функцию ProcessAll:

**Ключевые изменения:**
1. Добавлен канал `stopSending` для сигнала остановки горутине отправляющей jobs
2. Добавлен буферизованный канал `jobsCountChan` для отправки количества отправленных jobs
3. Горутина отправляющая jobs теперь:
   - Проверяет `stopSending` перед отправкой каждого job
   - Проверяет `ctx.Done()` перед отправкой 
   - Закрывает канал jobs через defer при выходе
   - Сообщает главному потоку сколько jobs было отправлено
4. Главный цикл теперь:
   - Закрывает `stopSending` при первой ошибке (флаг `stopSent` предотвращает двойное закрытие)
   - Закрывает `stopSending` при отмене контекста
   - Получает актуальное количество jobs которые нужно обработать через `jobsCountChan`
   - Продолжает обрабатывать outcomes до получения всех результатов от отправленных jobs

**Как исправлены проблемы:**
- Горутины больше не растут: при ошибке stopSending закрывается, job-sender выходит и закрывает jobs канал, workers выходят из цикла
- fn не вызывается после возврата: job-sender проверяет stopSending перед отправкой каждого нового job

### Проведены проверки

**Тесты:**
- TestProcessAll - базовая функциональность
- TestProcessAllError - обработка ошибок
- TestStopsAcceptingAfterError - проверка что новые элементы не отправляются после ошибки
- TestContextCancellation - обработка отмены контекста
- TestParallelExecution - проверка параллельного выполнения

**Результаты:**
✓ Все тесты проходят (5 тестов)
✓ Race detector не находит гонок данных: `go test -race` PASS
✓ Повторные запуски стабильны: тесты прошли 3 раза подряд успешно
✓ Нет ошибок от go vet
✓ Код компилируется без ошибок

Контракт функции сохранен: ProcessAll прекращает выдавать новые элементы при первой ошибке и не возвращает управление, пока не завершатся все уже начатые вызовы fn.

# Испытания go-zdorovogo-cheloveka

Стенд для проверки, как модель решает типичные Go-задачи со скиллом и без него. Каталог не входит в устанавливаемый скилл.

## Кейсы

| Кейс | Задача исполнителю | Что ловит оценщик |
|------|--------------------|-------------------|
| `e01-errors` | Сервис не стартует с корректным конфигом; `errors.Is(err, fs.ErrNotExist)` не срабатывает | typed nil в `error`, `%w`, `errors.As`, nil-конфиг при ошибке |
| `e02-slices` | Аргументы первой команды подменяются аргументами второй | `append` в общий массив, изменение входного среза |
| `e03-cancel` | Растёт число горутин, `fn` выполняется после возврата | утечка горутин, ожидание начатой работы, отмена, ограничение параллелизма |
| `e04-race` | `concurrent map read and map write` в кэше | гонка без мьютекса, копирование `sync.Mutex` (`go vet`) |
| `e05-http` | Нет отмены, 404 без ошибки, копятся соединения | `NewRequestWithContext`, проверка статуса, закрытие body, экранирование пути |
| `e06-refactor` | Отрефакторить длинную функцию без изменения вывода | вывод байт в байт, `go 1.21` в `go.mod` (проверка на Go 1.21.13), сгенерированный файл, чужие незакоммиченные правки и неотформатированный файл коллеги, экспортируемый API |
| `e07-exec` | Аргументы как есть, раздельные stdout/stderr, код выхода, отмена | запуск без shell, `ExitCode`, `errors.Is(err, ctx.Err())`, сборка под Windows |

Структура кейса:

- `task.md` — запрос, который получает исполнитель;
- `project/` — исходный проект;
- `dirty/` — незакоммиченные правки, которые исполнитель застаёт в рабочем дереве;
- `grader/` — скрытые тесты оценщика;
- `reference/` — эталонное исправление (только изменённые файлы);
- `broken/*/` — заведомо неверные решения, которые оценщик обязан отклонить;
- `case.env` — дополнительные проверки кейса.

## Скрипты

```sh
./prepare.sh e03-cancel /tmp/ws/e03   # рабочая копия: git-репозиторий + dirty/
./grade.sh   e03-cancel /tmp/ws/e03   # оценка; рабочая копия не меняется
./verify.sh                           # самопроверка стенда
```

`grade.sh` проверяет:

- что не изменены `go.mod`, `go.sum`, сгенерированный код и файлы из `dirty/`;
- `gofmt` изменённых файлов;
- `go build` и `go vet`;
- скрытые тесты вместе с тестами проекта под `-race`;
- дополнительные проверки из `case.env`.

Итог — строка `RESULT PASS` или `RESULT FAIL`. Проверки кода оценщик не заменяет: diff всё равно просматривается вручную, чтобы оценить лишнюю сложность и качество отчёта.

`verify.sh` требует, чтобы эталон проходил, а исходный код (кроме `e06-refactor`) и все `broken/*` проваливались. Нужны Go 1.22+ с `gcc` для `-race` и доступ к `proxy.golang.org`, чтобы скачать Go 1.21.13.

## Протокол прогона

1. Для каждого прогона — отдельная рабочая копия `prepare.sh` вне этого репозитория.
2. Исполнитель — свежая сессия без доступа к плану, оценщику и эталону. Промпт:

   ```text
   Ты работаешь в Go-проекте в каталоге <WS>. Работай только в этом каталоге и не открывай другие каталоги на диске.
   [Со скиллом: Сначала прочитай <SKILL>/SKILL.md и следуй ему.]
   Не делай git commit.

   Задача от пользователя:
   <содержимое task.md>

   В конце кратко отчитайся: что изменено, какие проверки запущены и с каким результатом.
   ```

3. Без скилла и со скиллом всё одинаково, кроме строки про скилл: модель, промпт, инструменты.
4. После прогона: `grade.sh`, `git diff`, ручная оценка лишней сложности и честности отчёта.

Ограничения:

- исполнитель технически может прочитать файлы вне рабочей копии, поэтому промпт это запрещает, а трассы просматриваются;
- скилл загружается явной строкой в промпте, поэтому автоматическое срабатывание по `description` здесь не проверяется;
- поведение под Windows проверяется только сборкой.

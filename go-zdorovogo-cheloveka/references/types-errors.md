# Типы, ошибки и форма API

Правила описывают причину выбора, а не запрет конструкции. Сначала проверь контракт функции и то, что видит вызывающий; затем выбери самый простой вариант, который его выполняет.

## Ошибки

**Принцип:** ошибка — значение, которое вызывающий использует для решения. Верни её с контекстом, которого в ней ещё нет, или обработай в одном месте. Не логируй и не возвращай одну и ту же ошибку на каждом уровне: в логе окажется несколько копий одного сбоя.

**`%w` или `%v`.** `fmt.Errorf("...: %w", err)` делает причину частью API: вызывающие начнут проверять её через `errors.Is`/`errors.As`, и замена причины станет несовместимым изменением. Оборачивай `%w`, когда вызывающему нужно различать причину (`fs.ErrNotExist`, `context.Canceled`, ошибка твоего пакета). `%v` подходит, когда причина — деталь реализации, которую ты не хочешь обещать. С Go 1.20 `fmt.Errorf` принимает несколько `%w`, а `errors.Join` объединяет несколько ошибок.

**Контекст** добавляй тот, которого нет в исходной ошибке. Ошибки `os` уже содержат операцию и путь (`open /etc/app.json: no such file or directory`); повторять путь не нужно, достаточно назвать действие.

```go
var ErrNotFound = errors.New("store: запись не найдена")

// FieldError сообщает, какое поле некорректно.
type FieldError struct {
	Field string
}

func (e *FieldError) Error() string { return "некорректное поле " + e.Field }

type Settings struct {
	Port int `json:"port"`
}

func LoadSettings(path string) (*Settings, error) {
	data, err := os.ReadFile(path)
	if err != nil {
		return nil, fmt.Errorf("загрузка настроек: %w", err)
	}
	var s Settings
	if err := json.Unmarshal(data, &s); err != nil {
		return nil, fmt.Errorf("разбор настроек %s: %w", path, err)
	}
	if s.Port <= 0 {
		return nil, &FieldError{Field: "port"}
	}
	return &s, nil
}

func describe(err error) string {
	var fe *FieldError
	switch {
	case err == nil:
		return "ok"
	case errors.Is(err, fs.ErrNotExist):
		return "файла нет, берём значения по умолчанию"
	case errors.As(err, &fe):
		return "исправьте поле " + fe.Field
	default:
		return "сбой: " + err.Error()
	}
}
```

**Sentinel или тип.** Переменная (`ErrNotFound`) — когда важен только факт; тип (`*FieldError`) — когда вызывающему нужны данные. Сравнивай через `errors.Is`/`errors.As`, а не `==` или текстом `err.Error()`: обёртка ломает и то и другое. Цель `errors.As` — указатель на переменную того типа, который реализует `error` (`var fe *FieldError; errors.As(err, &fe)`).

**Проверка выбора:** может ли вызывающий по-разному реагировать на разные сбои? Если да — причина должна быть различима через `errors.Is`/`errors.As`. Строку ошибки пиши со строчной буквы и без точки в конце: её встраивают в другие сообщения.

### Typed nil

Интерфейс равен `nil`, только если в нём нет ни типа, ни значения. Nil-указатель конкретного типа, помещённый в `error`, даёт непустой интерфейс: `err != nil` истинно, а печатается `<nil>`.

```go
// Плохо: при корректном порте вернётся непустой error с nil-указателем внутри.
func checkPortBad(port int) error {
	var fe *FieldError
	if port <= 0 {
		fe = &FieldError{Field: "port"}
	}
	return fe
}
```

```go
func checkPort(port int) error {
	if port <= 0 {
		return &FieldError{Field: "port"}
	}
	return nil
}
```

**Проверка выбора:** функции возвращают `error`, а не `*MyError`. Если внутренняя функция возвращает конкретный тип, проверь его на `nil` до присваивания в `error`: `if fe := validate(); fe != nil { return nil, fe }`. Не исправляй typed nil так, что ломается другое обещание контракта: если документация говорит «при ошибке возвращает nil», результат при ошибке должен быть `nil`.

### panic, recover и выход из процесса

Ошибку, которую вызывают вход, файл, сеть или пользователь, возвращай. `panic` — для нарушенного инварианта программы (баг) и для `Must`-функций, вызываемых с константами при инициализации (`regexp.MustCompile`). Библиотека не паникует через границу своего API в ответ на данные вызывающего. `recover` уместен на границе запроса или горутины, где известно, как продолжить; `net/http` уже восстанавливает панику обработчика, но паника в горутине, которую ты запустил сам, завершает процесс.

`os.Exit` и `log.Fatal` не выполняют отложенные `defer`: файлы не сбрасываются, временные каталоги не удаляются. Вызывай их только в `main`, после освобождения ресурсов; ниже по стеку возвращай ошибку.

## nil и нулевые значения

- Нулевое значение типа по возможности полезно (`sync.Mutex`, `bytes.Buffer`, `strings.Builder` готовы к работе). Если нет — документируй «используйте `New`».
- Nil-срез и пустой срез оба имеют длину 0, но `encoding/json` кодирует первый как `null`, второй как `[]`. Если формат важен, выбери явно.
- Чтение из nil-map возвращает нулевое значение, запись в неё паникует.
- При ошибке возвращай нулевое значение или `nil` результата, если контракт не обещает другого. Не маскируй ошибку правдоподобным нулевым результатом без ошибки.

## Значение или указатель

- **Получатель-указатель**, если метод меняет получатель, тип содержит `sync.Mutex` или другое поле, которое нельзя копировать, или структура велика. Если у типа есть методы с указательным получателем, делай так все методы: смешение запутывает и копирует состояние.
- **Получатель-значение** — для маленьких неизменяемых типов (как `time.Time`) и типов-обёрток над map, функцией или каналом.
- Не передавай указатель на срез, map, канал, интерфейс или строку «чтобы не копировать»: это уже небольшие дескрипторы. Указатель на срез нужен, только если функция меняет сам срез вызывающего (его длину).
- Копирование структуры с мьютексом — ошибка: `go vet` (copylocks) сообщает о ней, включая метод с получателем-значением.

## Интерфейсы

**Принцип:** интерфейс объявляет потребитель, и он содержит только нужные ему методы. Производитель возвращает конкретный тип. Не создавай интерфейс к каждой структуре «для моков»: интерфейс появляется, когда есть вторая реализация или тесту нужна подмена внешней зависимости (сеть, время, файловая система).

```go
// Потребителю нужна только запись — принимаем io.Writer, а не *os.File.
func writeReport(w io.Writer, lines []string) error {
	for _, l := range lines {
		if _, err := fmt.Fprintln(w, l); err != nil {
			return err
		}
	}
	return nil
}
```

**Проверка выбора:** если у интерфейса одна реализация и нет теста с подменой — используй конкретный тип. Добавление метода в экспортируемый интерфейс ломает все внешние реализации. Явная проверка реализации — `var _ io.Writer = (*MyWriter)(nil)`.

## Срезы и map

**Общий массив.** Срез — окно в массив. `append` пишет в тот же массив, если хватает ёмкости, поэтому два результата `append` к одному срезу могут перезаписать друг друга, а фильтрация через `s[:0]` меняет вход.

```go
// Плохо: при свободной ёмкости base результаты двух вызовов делят один массив.
func withFlagsBad(base []string, extra ...string) []string {
	return append(base, extra...)
}
```

```go
// withFlags не меняет base и возвращает независимый срез.
func withFlags(base []string, extra ...string) []string {
	out := make([]string, 0, len(base)+len(extra))
	out = append(out, base...)
	return append(out, extra...)
}

// nonEmpty не меняет вход.
func nonEmpty(in []string) []string {
	out := make([]string, 0, len(in))
	for _, s := range in {
		if s != "" {
			out = append(out, s)
		}
	}
	return out
}
```

**Проверка выбора:** обещает ли контракт, что вход не меняется или что результаты независимы? Если да — копируй (`slices.Clone`, `maps.Clone` с Go 1.21, или `make` + `append`). Если функция документирована как изменяющая вход (фильтрация на месте ради памяти), `s[:0]` уместен. Возврат внутреннего среза или map из структуры отдаёт вызывающему её состояние, а под мьютексом — ещё и гонку: возвращай копию. Маленький подсрез большого массива держит весь массив в памяти; скопируй, если исходный больше не нужен.

**Порядок map** случаен. Для детерминированного вывода сортируй ключи: `sort.Strings(keys)` или `slices.Sorted(maps.Keys(m))` (Go 1.23+).

**Переменная цикла.** При строке `go` 1.22 и выше у каждой итерации `for` своя переменная; ниже — одна на весь цикл, и замыкание или горутина, захватившие её, видят последнее значение. В модуле с `go` < 1.22 копируй переменную (`v := v`) перед захватом.

## Строки и байты

`len(s)` — число байт, `s[i]` — байт, `for i, r := range s` идёт по рунам UTF-8, `utf8.RuneCountInString` считает руны. Резать строку по байтовому индексу можно только на границе руны. Преобразование `[]byte(s)` и `string(b)` копирует данные; для сборки строки в цикле используй `strings.Builder`. Не оптимизируй копирование через `unsafe` без измерения и согласия пользователя.

## Generics

Обобщённая функция оправдана, когда один и тот же алгоритм нужен для нескольких реальных типов: контейнеры, `slices`/`maps`-подобные утилиты. Если тип один — пиши конкретный. Если поведение типов различается — нужен интерфейс, а не параметр типа. Ограничения из стандартной библиотеки: `any`, `comparable`, `cmp.Ordered` (Go 1.21).

## Форма API

- `context.Context` — первый параметр функции, которая может блокироваться; не храни его в структуре.
- Конструктор `NewX` возвращает конкретный тип. Функциональные опции — для публичного конструктора с многими необязательными и развивающимися настройками; для двух-трёх параметров достаточно аргументов или структуры конфигурации.
- Литерал `true`/`false` в вызове не объясняет себя: при нескольких флагах или неочевидном смысле выбери именованный тип, константы или отдельные функции.
- Имена: пакет — короткое слово строчными без `_`; без повтора имени пакета (`report.Formatter`, а не `report.ReportFormatter`); геттер без `Get` (`Owner()`); аббревиатуры одним регистром (`URL`, `ID`, `userID`).
- У экспортируемого идентификатора есть doc-комментарий, начинающийся с его имени.

## Версии Go

Строка `go` в `go.mod` задаёт минимальную версию. Возможности языка новее неё компилятор отвергает; символы стандартной библиотеки новее неё компилятор пропускает, но о них сообщает `go vet` (анализатор stdversion, Go 1.23+). Для версий новее этой таблицы проверяй `go doc` и [заметки о выпусках](https://go.dev/doc/devel/release).

| Версия | Что появилось |
|--------|---------------|
| 1.18 | generics, `any`, `comparable` |
| 1.19 | типы `atomic.Int64`, `atomic.Bool` и др.; `exec.LookPath` не ищет в текущем каталоге (`exec.ErrDot`) |
| 1.20 | `errors.Join`, несколько `%w`; `context.WithCancelCause`, `context.Cause`; `exec.Cmd.Cancel`, `exec.Cmd.WaitDelay`; `http.ResponseController` |
| 1.21 | встроенные `min`, `max`, `clear`; пакеты `slices`, `maps`, `cmp`, `log/slog`; `sync.OnceFunc`/`OnceValue`; `context.AfterFunc`, `context.WithoutCancel`; строка `go` стала обязательным минимумом, `toolchain` |
| 1.22 | своя переменная цикла на итерацию; `for i := range n`; `math/rand/v2`; шаблоны `http.ServeMux` с методом и `{name}`, `Request.PathValue`; `slices.Concat`, `cmp.Or` |
